01 Ringkasan Eksekutif

Dokumen ini memetakan arsitektur, menu, dan seluruh endpoint API layanan Zenith Trading (produk analisa saham di dalam platform JadiAI), direkonstruksi dari rekaman lalu lintas jaringan (console.jadiai.com.har) saat Anda login dan menelusuri menu-menunya. Tujuannya: bahan belajar untuk membangun padanannya di proyek analisis_saham Anda.

🌐 Arsitektur

SPA console.jadiai.com memanggil REST API di jadiai.com/api/v1. Backend Laravel / PHP 8.2 (Apache, CentOS).

🔐 Autentikasi

Login → token Laravel Sanctum (format <id>|<hash>). Billing token/saldo via Midtrans.

🧩 30 endpoint

Terbagi jadi plumbing akun (login, watchlist, jurnal — plaintext) dan inti analisa (market-data, sinyal, screener).

🔒 Temuan kunci

Semua endpoint analisa mengembalikan payload AES terenkripsi {payload, iv} — data proprietary sengaja disembunyikan.

⚠️ Batas yang saya pegang

Dokumen ini tidak mendekripsi atau mengekstrak isi data proprietary Zenith. Yang dipetakan adalah permukaannya: fitur, kontrak API, parameter, dan jenis data tiap endpoint — semuanya terlihat sah dari sisi klien Anda sendiri. Untuk membongkar kunci AES demi menyalin nilai/skor aktual mereka tidak saya lakukan (lihat bagian 09). Konsep analisanya sendiri (bandarmology, seasonality, valuasi, dsb.) adalah teknik finansial umum yang bebas Anda bangun sendiri.

03 Autentikasi & Model Bisnis

Alur autentikasi

  • POST /member/login dengan {email, password} → mengembalikan objek member + token Sanctum ("936|8VCz…").
  • Token disimpan klien, dikirim di request berikutnya (skema Bearer / Sanctum). Catatan: header Authorization tidak ikut terekam di HAR ini, tapi skema token jelas dari respons login.
  • GET /member/me → profil + kapabilitas + daftar harga + kontak.
  • POST /member/logout → {"message":"Berhasil logout"}.

Model bisnis (dari /member/me & /payment/deposit-data)

Platform induk

JadiAI = platform AI (teks/gambar/video, 166 baris pricing_list model seperti gemini-2.5-pro, sora-2). Zenith Trading = modul premium di dalamnya.

Langganan

Plan "Zenith Trading Monthly" (plan_id 7) — Rp 49.900/bln via Midtrans. Invoice ZEN-185-….

Token / saldo

Beli plan memberi bonus deposit (mis. Rp 7.500 kredit). Pemakaian diukur token; endpoint token-stats & token-history melacak saldo.

Biaya & pajak

ppn_percent: 11, member_markup_percent: 15, additional_fee.zenith: 75, fee_basic_topup: 3500.

04 Peta Menu / Fitur

Direkonstruksi dari pola pemanggilan endpoint saat menelusuri aplikasi. Delapan area fungsional:

① Market Scanner

Daftar saham diperingkat oleh skor komposit (sort_by=score). Layar utama; juga dipakai sebagai lookup 1 simbol.

/zenith/market-scanner

② Analisa Emiten (detail)

Buka 1 saham → memuat 11 modul data: harga historis, aksi, money-flow, keystats, seasonality, broker-summary, komposisi, financials, corporate-actions, major-holders.

/zenith/market-data/*

③ Sinyal Trading

Tiga strategi bernama: rebound, pucuk, bpjs. Daftar saham yang memicu sinyal (paginated, bisa difilter simbol).

/market-data/signals/{rebound|pucuk|bpjs}

④ Evaluasi / Backtest

Harian (hasil sinyal per tanggal) & Akumulasi (di-sort win_rate_overall → evaluasi performa historis).

/market-data/evaluasi/{harian|akumulasi}

⑤ Screener

Tematik (sektor/tema), Valuasi (murah/mahal), Dividen (yield). Daftar saring lintas emiten.

/market-data/{screener/thematic|valuation|dividen}

⑥ Watchlist

Daftar pantau pribadi. GET daftar, POST tambah simbol (mis. {"symbol":"EMTK"}).

/zenith/watchlist

⑦ Jurnal Trading

Catat transaksi BUY/SELL (price, lot, subtotal, broker). Simpan batch. Pondasi analisa P&L pribadi.

/zenith/history · /zenith/history/batch

⑧ Akun & Token

Profil, saldo, riwayat token, deposit/langganan, pengumuman.

/member/* · /payment/* · /announcements

06 Kamus Data — Konsep Tiap Modul

Apa arti tiap modul analisa dan gunanya untuk keputusan trading/investasi. Ini konsep umum yang bisa Anda bangun sendiri.

Kelompok Harga & Teknikal

historis

OHLCV harian hingga ~1500 hari (≈6 th). Pondasi semua indikator teknikal, return, volatilitas, seasonality, backtest.

stock-actions

Penyesuaian harga akibat aksi (split, bonus, right). Penting agar seri harga "adjusted" akurat.

seasonality

Pola return per bulan/periode secara historis — bulan mana cenderung hijau/merah. chart untuk 1 saham, highlights lintas saham.

keystats

Statistik ringkas: kapitalisasi, PER, PBV, dsb. — kartu ikhtisar di halaman emiten.

Kelompok Bandarmology (kekhasan Zenith) butuh data IDX khusus

broker-summary

Net buy/sell per broker (rentang tanggal). Melacak akumulasi/distribusi "bandar". Butuh data transaksi broker IDX (Stockbit/IDX).

money-flow-history

Aliran dana masuk/keluar (sering: asing vs ritel) dari waktu ke waktu — indikator tekanan beli/jual.

composition

Komposisi kepemilikan (asing/lokal, institusi/ritel) time-series. Sumber tipikal: KSEI.

major-holders

Pergerakan pemegang saham utama dari waktu ke waktu.

Kelompok Fundamental

financials

Laporan keuangan tahunan (pendapatan, laba, ekuitas, dll.). Bahan valuasi & kualitas.

valuation (screener)

Saring saham murah/mahal berbasis rasio valuasi.

dividen (screener)

Saring berdasarkan dividend yield / kebijakan dividen.

corporate-actions

Kalender aksi korporasi (dividen, RUPS, split, right) — dasar event study.

Kelompok Sinyal & Evaluasi

market-scanner (score)

Skor komposit multi-faktor untuk memeringkat seluruh universe — inti "rekomendasi" Zenith.

signals: rebound / pucuk / bpjs

Tiga strategi entry bernama. "pucuk" ≈ deteksi awal tren naik; "bpjs" ≈ strategi internal; "rebound" ≈ pantulan dari oversold.

evaluasi/akumulasi (win_rate)

Backtest performa sinyal: win_rate_overall = % sinyal yang profit. Kredibilitas strategi.

evaluasi/harian

Rekap sinyal yang muncul & hasilnya per tanggal — jejak akuntabilitas harian.

09 Soal Enkripsi & Batas Etis

Kenapa dokumen ini tidak mendekripsi payload

Zenith sengaja mengenkripsi response analisanya (AES {payload,iv}) supaya isinya tidak terbaca dari Network tab. Membongkar kunci AES dari bundle JS mereka untuk mengekstrak & menyalin nilai/skor proprietary secara massal adalah tindakan yang (a) hampir pasti melanggar Ketentuan Layanan mereka, dan (b) berpindah dari "belajar" ke "mengkloning produk". Karena itu tidak saya lakukan.

Yang sah & produktif untuk tujuan Anda

  • Pelajari konsepnya, bukan datanya. Bandarmology, seasonality, valuasi, win-rate backtest — semua teknik finansial umum. Bangun versi Anda dari sumber data Anda sendiri.
  • Pakai sebagai referensi fitur/UX. Peta menu & katalog API di atas cukup untuk merancang fitur setara tanpa menyentuh data mereka.
  • Untuk memahami satu output, baca langsung di UI Zenith (Anda pelanggan sah) — bukan men-scrape massal.
